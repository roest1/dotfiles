==============================================================================
OVERVIEW                                                     *dotfiles-commands*

This file documents custom commands and key tooling in this Neovim setup.

These commands are designed to work together as a lightweight workflow system
for navigation, refactoring, and exporting code context.

------------------------------------------------------------------------------
WORKFLOW                                                     *dotfiles-commands-flow*

Typical workflow:

    :Find service
    :args
    :next
    :FindReplace old new
    :Copy -r --dir_match=services --ext=cs

Command roles:

    :Find           -> locate relevant files quickly
    :args/:next     -> navigate result set
    :FindReplace    -> perform controlled refactors
    :Copy           -> export context for AI/docs

:FIND                                                        *dotfiles-commands-find*

Find files containing a keyword using ripgrep.

Usage:~
    :Find <keyword>

Behavior:~
    - Executes: rg -l <keyword>
    - Populates the args list with matching files
    - Enables navigation via :args, :next, :prev

Notes:~
    - Uses ripgrep (fast, respects .gitignore by default)
    - Returns file paths only (not match locations)

Example:~
    :Find TODO
    :args
    :next
    :prev

Location: lua/external/findreplace.lua

==============================================================================
:FINDREPLACE                                          *dotfiles-commands-findreplace*

Find and replace text across all matching files.

Usage:~
    :FindReplace <find> <replace>

Behavior:~
    1. Uses ripgrep to locate files containing <find>
    2. Loads files into args list
    3. Executes:
        :argdo %s/<find>/<replace>/gc | update

Prompt options:~
    y  -> replace
    n  -> skip
    a  -> replace all remaining in file
    q  -> quit
    l  -> replace current and quit

Limitations:~
    - Arguments are space-delimited (no quoting support)
    - Does not support spaces in <find> or <replace>
    - Uses Vim regex (not literal unless escaped)

Example:~
    :FindReplace oldFunction newFunction

Location: lua/external/findreplace.lua

:COPY                                                        *dotfiles-commands-copy*

Copy file contents to clipboard for external use (AI, docs, sharing).

Usage:~
    :Copy [options]

Core Behavior:~
    - Detects file set using:
        1. git ls-files (preferred, respects .gitignore)
        2. fd (fallback)
        3. find (final fallback)
    - Skips binary files automatically
    - Outputs structured file blocks to clipboard

Output format:~
    --- Start of /path/to/file ---
    <file contents>
    --- End of /path/to/file ---

Options:~
    -r, --recursive
        Include subdirectories

    --match=<pattern>
        File path must contain pattern (AND logic)
        Example: --match={api,controller}

    --dir_match=<pattern>
        File must be inside matching directory (OR logic)
        Example: --dir_match={src,lib}

    --exclude=<pattern>
        Exclude files containing pattern

    --ext=<ext>
        Filter by file extension (no dot)
        Example: --ext={cs,ts}

    --max=<n>
        Limit number of files (default: 100)

    --no-gitignore
        Disable .gitignore filtering

Filtering semantics:~
    - --match -> ALL patterns must match (AND)
    - --dir_match -> ANY directory match is valid (OR)

Examples:~
    :Copy
    :Copy -r
    :Copy --ext=cs
    :Copy -r --dir_match=services --ext=cs
    :Copy -r --match={api,controller} --exclude=test

Recommended usage (Oil):~
    1. Press `-` to open directory view
    2. Navigate to target directory
    3. Run :Copy with desired filters

Location: lua/external/copy.lua

:RESETNVIM                                                *dotfiles-commands-reset*

Reset Neovim environment (destructive).

Usage:~
    :ResetNvim      (confirmation prompt)
    :ResetNvim!     (force)

Deletes:~
    ~/.local/share/nvim     (plugins, tree-sitter parsers)
    ~/.cache/nvim           (cache)

After execution:~
    1. Restart Neovim
    2. Plugins reinstall via Lazy

Language servers are NOT affected. They live outside these directories —
native ones on PATH from ../deps.conf, the JavaScript ones in
nvim/lsp-servers/node_modules — so a reset never costs you the toolchain.
That was not true under Mason, which kept its installs in
~/.local/share/nvim/mason and lost them with every reset.

When to use:~
    - Plugin corruption
    - Persistent unexplained errors
    - Full environment reset

Location: lua/external/reset.lua

:RENDER                                                    *dotfiles-commands-render*

Toggle in-buffer markdown rendering for the current buffer.

Usage:~
    :Render

Behavior:~
    - Off by default; markdown files open as raw source
    - While on, normal mode shows the rendered view and insert mode shows raw
      source, so motions land on text you can see the cursor over
    - Running it again turns rendering back off for the buffer

Location: lua/external/plugins/render-markdown.lua

:PASTEIMAGE                                            *dotfiles-commands-pasteimage*

Paste an image from the OS clipboard into a directory as a PNG. Pairs with Oil
for a "screenshot → snip → paste" workflow. See |dotfiles-plugins-pasteimage|.

Usage:~
    :PasteImage                     Screenshot-YYYYMMDD-HHMMSS.png
    :PasteImage --rename name.png   name.png  (.png added if no extension)

Behavior:~
    - In Oil       -> writes to the directory Oil is showing, then refreshes
    - Elsewhere    -> writes to the current file's directory, else the cwd
    - Won't overwrite an existing file

Backend (auto-detected):~
    WSL2            Windows PowerShell    (no install)
    Linux/Wayland   wl-paste              (pkg: wl-clipboard)
    Linux/X11       xclip                 (pkg: xclip)
    macOS           pngpaste              (brew), else osascript

Location: lua/external/pasteimg.lua

:KEYMAPUSAGE                                            *dotfiles-commands-usage*
                                                                 *:KeymapUsage*

How often each mapping has actually been pressed.

Usage:~
    :KeymapUsage            every current mapping, zeros first
    :KeymapUsage reset      delete the record and start over

Behavior:~
    - lua/external/usage.lua watches typed keys in normal and visual mode and
      matches them against the mappings active in the buffer, so a count is a
      real press of that mapping, not a key that happened to appear in text
    - Written to stdpath('state')/keymap-usage.json -- ~/.local/state/nvim,
      which is OUTSIDE the work tree. It cannot be committed by accident
      because git never sees it. Do not move it under the config directory,
      which is a symlink into the repo.
    - Flushed every 25 presses and on exit; two running editors merge rather
      than overwrite

Why:~
    The June 2026 cleanup deleted ~40 mappings on judgement and this help
    kept describing them for four months. The next cleanup should delete
    zeros instead. tools/usage.sh in the repo root does the same for the
    shell and prints both halves together.

Location: lua/external/usage.lua

:ALTFONT                                              *dotfiles-commands-altfont*

Report or toggle the alternate-font carrier -- file buffers drawn in a
different wezterm font from oil, telescope and the chrome.

Usage:~
    :AltFont                what it decided and why
    :AltFont toggle         off for this session

Only active under wezterm with this repo's config linked; anywhere else the
attribute it uses would mean blinking text, so it refuses. The mechanism and
the three things not to "tidy" are in nvim/CLAUDE.md.

Location: lua/external/altfont.lua

LANGUAGE SERVERS                                   *dotfiles-commands-servers*

There is no Mason and no :Mason command. Servers are declared ahead of time
rather than installed from inside the editor, so there is nothing to open.

Native binaries — clangd, lua-language-server, lemminx:~
    Declared in ../deps.conf under [nvim].
    Install:  make install nvim     (from the dotfiles root)

npm-published — tsc, bashls, yamlls, jsonls, cssls, html — and prettier:~
    Declared in nvim/lsp-servers/package.json, run as `bun <path>`; tsc
    is TypeScript 7's native binary and runs directly, with no runtime.
    Install:  bun install --cwd nvim/lsp-servers
    Update:   make -C nvim servers  (applies a 7-day release cooldown and
                                     regenerates yarn.lock)
    Verify:   bun nvim/lsp-servers/verify.ts
              proves all six complete a real LSP handshake

Why not Mason: it installs npm packages by shelling out to `npm`, which only
exists if node does. Dropping it is what removed node from this config
entirely. See the parent repo's CLAUDE.md.
