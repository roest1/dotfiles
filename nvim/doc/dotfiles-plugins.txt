*dotfiles-plugins.txt*    Plugin Reference

==============================================================================
PLUGINS                                                        *dotfiles-plugins*

Every plugin in lua/external/plugins/init.lua, what it does, and the keys or
commands it adds. Run `:Lazy` to see plugin status.

There is no completion plugin. blink.cmp sat in the list as `enabled = false`
from June to October 2026, so the editor ran without one for four months
while this file described its keymaps; the spec was deleted rather than
kept disabled. LSP servers get Neovim's own capabilities (lsp.lua). If a
completion engine comes back, that is the line it extends.

TELESCOPE                                              *dotfiles-plugins-telescope*

Fuzzy finder for files, text, help, keymaps, and more.

Location: lua/external/plugins/telescope.lua

Keymaps:
    <leader>sf      Find files
    <leader>sg      Grep text in project

Everything else is `:Telescope <picker>`; see |dotfiles-keymaps-telescope|.
telescope-ui-select routes `vim.ui.select` (code actions, among others)
through a dropdown.

Dependencies: plenary.nvim, telescope-fzf-native.nvim, telescope-ui-select.nvim

OIL                                                          *dotfiles-plugins-oil*

File browser that works like a buffer. Edit filenames to rename!

Location: lua/external/plugins/oil.lua

Keymaps:
    -               Open parent directory (replaces netrw)
    <leader>-       Open in floating window

Inside Oil:
    <CR>            Enter directory / open file
    -               Go up one directory
    g?              Show help
    <C-c>           Close

Edit the buffer to rename/delete/create files, then :w to apply.

Commands:
    :OilColumns             Show which optional columns are on
    :OilColumns mtime size  Toggle columns (mtime size atime ctime birthtime
                            type permissions); icon is always on

<CR> on a PDF or a raster image (.png .jpg .jpeg .gif .webp .bmp .avif) hands
the file to the OS's default viewer instead of opening it. Nothing is loaded
into a buffer -- you stay in Oil. Same for `nvim x.pdf` and :e. To read the
raw bytes anyway, use `:noautocmd e file.pdf`.

.svg is deliberately not in that list: it is text, and worth editing in a
buffer. Images are not rendered inside nvim because wezterm's kitty graphics
support is too incomplete for snacks.image or image.nvim to rely on.

Under WSL the file goes to the WINDOWS default viewer, via explorer.exe. It
does not go through vim.ui.open there: nvim tries xdg-open before wslview, and
WSLg supplies a working xdg-open, so the file would be handed to whatever
Linux desktop entry the guest happens to have -- xpdf for a .pdf, and for a
.png usually nothing at all, failing into a discarded stderr. See the comment
above os_open() for the whole chain.

On a machine with no desktop handler at all (headless RHEL, a container), it
warns and loads the file normally instead -- the same binary buffer you got
before this existed. It never becomes a silent no-op.

Location: lua/options.lua (BufReadCmd autocmd)

Git diffstat ~

Inside a git repo, each changed file shows its diff floated at the window's
right edge, matching the git section of the bash PS1:
    +N              Added lines (green), total vs the last commit (HEAD)
    -N              Deleted lines (red), total vs the last commit
    +N (untracked)  Line count of a new/untracked file

Combines staged and unstaged changes. Commands:
    :OilGit         Toggle the diffstat overlay on/off

Location: lua/external/oilgit.lua (loaded from oil.lua's config)

Paste image from clipboard ~                       *dotfiles-plugins-pasteimage*
                                                                  *:PasteImage*

Drop an image off the OS clipboard into a directory as a PNG -- the
"screenshot -> snip -> paste into Oil" workflow, like pasting a file in a GUI
file manager.

    1. Take a screenshot to the clipboard:
         Windows/WSL   Win+Shift+S         (Snipping Tool)
         macOS         Cmd+Ctrl+Shift+4    (region -> clipboard)
         Linux         your snipper's "copy to clipboard" option
    2. Open Oil at the destination directory (`-`).
    3. Run a command:
         :PasteImage                    Screenshot-YYYYMMDD-HHMMSS.png
         :PasteImage --rename name.png  name.png  (.png added if no extension)

The file is written to disk and Oil refreshes to show it. Outside Oil the
image lands in the current file's directory (or the cwd).

The clipboard backend is detected at runtime, so the same command works
everywhere:
    WSL2            Windows PowerShell        (no install needed)
    Linux / Wayland wl-paste                  (pkg: wl-clipboard)
    Linux / X11     xclip                     (pkg: xclip)
    macOS           pngpaste                  (brew), else osascript

The per-platform tool is installed by nvim/deps.sh (`make install nvim`);
verify with `:checkhealth external`.

Location: lua/external/pasteimg.lua

LSP                                                          *dotfiles-plugins-lsp*

Language Server Protocol -- code intelligence.

Location: lua/external/plugins/lsp.lua

Configured servers:
    lua_ls          Lua
    tsc             TypeScript/JavaScript (TypeScript 7, native)
    clangd          C/C++
    cssls           CSS
    html            HTML
    jsonls          JSON
    yamlls          YAML
    bashls          Bash
    lemminx         XML
    roslyn          C# (separate plugin, see |dotfiles-plugins-roslyn|)

Keymaps (when LSP is attached):
    grd             Go to definition
    grD             Go to declaration
    grr             Find references
    gri             Go to implementation
    grt             Go to type definition
    grn             Rename symbol
    gra             Code action (fixes, refactors)
    gO              Document symbols
    gW              Workspace symbols

Related: fidget.nvim (LSP progress in the corner), lazydev.nvim (Lua-specific
library paths). No mason.nvim -- servers are declared, not installed from the
editor. See |dotfiles-commands-servers|.

CONFORM (FORMATTER)                                  *dotfiles-plugins-formatter*

Auto-formatting on save, plus <leader>l on demand. The on-save hook lives in
lua/options.lua as a BufWritePre autocmd -- see |dotfiles-keymaps-formatting|.

Location: lua/external/plugins/formatter.lua

Keymaps:
    <leader>l       Format file (or selection in visual mode)

Formatters by filetype:
    lua                 stylua
    javascript          prettier
    typescript          prettier
    typescriptreact     prettier
    javascriptreact     prettier
    json, jsonc         prettier
    markdown            prettier
    html                prettier
    css                 prettier
    yaml                prettier
    python              ruff

prettier is declared in nvim/lsp-servers/package.json and run as
`bun <path> --write`, the same way the language servers are. `--write` on
the file, not stdin: prettier's stdin mode exits 0 and writes nothing under
bun.

Not listed, and deliberately: bash and toml. prettier has no parser for either
("No parser could be inferred"), so those mappings never worked. shfmt and taplo
are the usual answers if you want them -- both native binaries, a deps.conf line
each, no JavaScript involved.

NVIM-LINT (LINTER)                                      *dotfiles-plugins-lint*

Async linting alongside LSP diagnostics.

Location: lua/external/plugins/lint.lua

Linters by filetype:
    python              ruff

That is the whole table. eslint_d was listed for JS/TS for months after node
left and nothing installed it, so the entry linted nothing. A mapping is only
as real as the binary behind it: to lint JS/TS, add eslint to
nvim/lsp-servers/package.json, run it through bun the way prettier is, and
add the table entry in the same commit.

Runs on: save, insert-leave, buffer read.

GITSIGNS                                                *dotfiles-plugins-gitsigns*

Git gutter signs and hunk navigation.

Location: lua/external/plugins/gitsigns.lua

Signs:
    +       Added line
    ~       Changed line
    _       Deleted line (below)
    ‾       Deleted line (above)

Keymaps:
    ]c              Next change
    [c              Previous change

Staging and blame are `:Gitsigns stage_hunk`, `:Gitsigns blame_line`,
`:Gitsigns preview_hunk`. The leader-h mappings that wrapped them were
deleted in 37fa6ce. The statusline reads gitsigns' branch name
(lua/options.lua).

TROUBLE                                                  *dotfiles-plugins-trouble*

Diagnostics and symbol lists in a panel. Command-only; lazy-loaded on first

Location: lua/external/plugins/trouble.lua

Commands:
    :Trouble diagnostics    All diagnostics
    :Trouble symbols        Symbols outline
    :Trouble lsp            References / definitions
    :Trouble qflist         Quickfix list

Inside Trouble: q to close, <CR> to jump, j/k to navigate.

WHICH-KEY                                              *dotfiles-plugins-which-key*

Shows available keymaps in a popup after pressing leader.

Location: lua/external/plugins/which-key.lua

Press <Space> and wait 300ms -> popup shows the leader keymaps. One group is
declared, [S]earch, because <leader>s is the one prefix with two keys under
it. Declare another only when a second mapping shares a prefix; which-key
shows an empty group without complaint, which is how four stale ones
survived for months.

MINI (SURROUND)                                          *dotfiles-plugins-mini*

Surround: manipulate surrounding characters. Only mini.surround is loaded;
there is no mini.pairs.

Location: lua/external/plugins/mini.lua

Keymaps:
    sa{motion}{char}  Add surrounding (e.g. saiw" -> surround word with ")
    sd{char}          Delete surrounding (e.g. sd" -> remove quotes)
    sr{old}{new}      Replace surrounding (e.g. sr"' -> " to ')
    sf / sF           Find next / previous surrounding
    sh                Highlight surrounding
    sn                Set how many lines sf/sF search

ROSLYN                                                    *dotfiles-plugins-roslyn*

C# language server (Microsoft's Roslyn), through roslyn.nvim. It is also
what sets this config's Neovim floor: the plugin refuses to load below 0.12.

Location: lua/external/plugins/roslyn.lua

The server is `roslyn-language-server`, a dotnet global tool, declared
`manual` in ../deps.conf and installed by nvim/deps.sh wherever `dotnet`
exists. dotnet itself is a project toolchain this repo does not install.
By hand:

    dotnet tool install -g roslyn-language-server --prerelease \
      --source https://pkgs.dev.azure.com/azure-public/vside/_packaging/vs-impl/nuget/v3/index.json

It lands in ~/.dotnet/tools, which bashrc puts on PATH. The plugin looks for
it there by name and nowhere else.

Commands:
    :Roslyn target          Change solution target
    :Roslyn restart
